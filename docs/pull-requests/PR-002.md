# PR-002: Foundation (template, policies, caching, Dispatcher, sample package)

**Branch:** `feature/foundation` → `main` (merged `--no-ff`)
**Type:** platform foundation. The page shell, configuration and delivery rules come before any feature components.

## Why

The hero, Joey Club teaser and travel-questions components each need a template that renders landmarks, policies that limit what authors can place, the freshness budget (ADR-004), and a Dispatcher allow-list. Putting these in a single PR keeps the feature PRs small and focused on behaviour.

## What changed

- **Archetype clean-up.** Removed the components, servlets, listeners, schedulers, CIF pages and sample assets that the solution doesn't use. The components kept are page, container, experience fragment, xfpage, navigation, text, image and teaser.
- **Template `travel-information-page`** (renamed from `page-content`):
  - The structure holds the header XF, then `container` (the `<main>`, `id="main-content"`) with an editable `content` child, then the footer XF.
  - Landmarks come from Style System default elements (ADR-008, revised during build). Skip-to-content comes from Core Page with `mainContentSelector=main-content`.
- **Policies.** Only the teaser and travel-questions components are allowed in `content`. The image policy uses the 320–1280 widths, lazy loading and DAM alt text. The teaser `policy_joeyclub` hides the pretitle and link. The travel-questions policy sets the default heading levels.
- **Tags.** `airline:travel/*` and `airline:market/{au,nz}`.
- **Packaging.**
  - `ui.content` ships code-owned subtrees only, with filter modes update/replace/merge per root.
  - The `/conf/airline/...` ancestors and the `/content/dam/airline` root are created by repoinit.
  - New module `ui.content.sample` holds the demo site and XFs (ADR-019). `all` embeds it, and removing that embed gives a production build.
- **Caching (ADR-004).** `HtmlCacheHeadersFilter` (publish only, `configurationPolicy=REQUIRE`) emits:
  - `Cache-Control: max-age=60`
  - `Surrogate-Control: max-age=150, stale-while-revalidate=30, stale-if-error=86400`
  - `Surrogate-Key: airline-page-<hash>`

  It covers successful page HTML only and doesn't override headers that are already set. JaCoCo now enforces 80% line coverage per bundle.
- **CORS.** A publish CORS policy for the persisted-query endpoint only. The origin comes from the env var `AIRLINE_GRAPHQL_ALLOWED_ORIGIN`, and credentials are not allowed.
- **Dispatcher.**
  - `airline.vhost` sets the security headers and the static-asset cache rules. `airline.farm` passes through the surrogate and CORS headers.
  - The filter is an allow-list with no default filters.
  - `DISABLE_DEFAULT_CACHING` and `CACHE_GRAPHQL_PERSISTED_QUERIES` are set, and `Origin` is added to the client headers.
- **Frontend.**
  - Node 24.22.3 and npm 11.19.1.
  - `main.ts` now uses explicit imports. The old glob also matched `main.ts` itself, which made webpack recurse until it overflowed the call stack.
  - Added `datalayer.ts` (`pushEvent`, `readComponentData`).
