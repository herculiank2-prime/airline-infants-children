# PR-004: Travel questions from Content Fragments, persisted queries and FAQ JSON-LD

**Branch:** `feature/travel-questions` → `main` (merged `--no-ff`)
**Stories:** AC-01 (accordion), HD-01 (fragments), HD-02 (persisted query), SE-01 (structured data), DL-01 (accordion events)

## Why

The six "Booking for infants (under 2 years)" items are legally reviewed copy that must appear identically on the page, in FAQ structured data and in a non-AEM app. ADR-002 makes them Content Fragments; this PR builds that path end to end.

## What changed

- **Content Fragment model `travel-question`** (`ui.content`, `mode="replace"`): `question` (required, 255), `answer` (required rich text), `tags` (rooted at `airline:`, no auto-create), `sortOrder` (required, default 100, ADR-016). It was first created in the author UI, then exported into Git so the model is code-owned.
- **Six fragments** (`ui.content.sample`) in `/content/dam/airline/travel-questions/infants`, titles from the reference page, placeholder answers written for the fictional airline. Each is tagged `travel/infants`, `market/au` and `market/nz`. The folder carries `cq:conf=/conf/airline`.
- **GraphQL** (`ui.content`): endpoint `/content/cq:graphql/airline/endpoint` and three persisted queries, `travel-questions-by-folder`, `-by-tag` and `-by-tags-all`, each with `cache-control: max-age=60` and `surrogate-control: max-age=150, stale-while-revalidate=30, stale-if-error=86400` (SD-08).
- **Java (`core`).**
  - `TravelQuestionService` + `TravelQuestionServiceImpl`: folder descendants or exact tag IDs (any/all), allowed-root check (rejects `..` and sibling prefixes), model check, required-field check, `sortOrder` then `question` ordering, limit, scan cap of 100 with truncation flag. OSGi config in `ui.config`.
  - `QuestionSelection.fromValueMap`: the single factory both models use.
  - `TravelQuestionsAccordion` / `AccordionItem` (models package) and `TravelQuestionsAccordionImpl`: heading levels from policy (validated `h2`–`h6`), stable item IDs from the fragment path, data-layer entries with `parentId`.
  - `FaqStructuredData` / `FaqStructuredDataImpl`: one FAQPage per page across all accordions, de-duplicated, reusing the request-cached selection (`SelectionCache`).
  - `RichTextSanitizer` (allow-list) and `FaqSchemaBuilder` (Gson, HTML-safe).
- **Component `airline/components/travelquestions`**: dialog with Content and Questions tabs (folder or tags with show/hide), HTL following the WAI-ARIA accordion pattern, `hidden="until-found"` panels, edit-mode truncation warning, placeholder when empty.
- **Page head**: FAQPage JSON-LD and the `<noscript>` fallback (ADR-018) in `customheaderlibs.html`.
- **Front end**: `travelquestions.ts` (click toggle, `beforematch`, `airline:accordion:expand|collapse` with `trigger`), `_travelquestions.scss`.
- **Demo content**: the accordion on `flying-infants-children` (tag mode, all, `infants` + `market/au`, `id="booking-infants"` so the hero jump link resolves) and a `component-states` page (decorative hero, folder mode with first item open, unconfigured accordion; `noindex`).
- **Tooling**: `scripts/aem-http.ps1` (ADR-021).
- **Clean-up on author**: deleted the leftover `Probe` fragment, the hand-made `travel-questions` folders, a temporary export package and a probe persisted query, so the packages own every node.

## Risks

- **Variable encoding.** Either leave the `;name=value` tail unencoded or encode all of it. Encoding only the values (as the v1.1 design showed) makes AEM drop the variables (ADR-022).
- **Fragments read from JCR, not the Content Fragment API** (ADR-023). Couples the service to the structured-fragment storage layout.
- **Sample content uses `merge`.** Redeploying does not update a page that already exists; delete it first (README).
