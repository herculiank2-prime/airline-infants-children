# PR-009: Author-configurable click tracking (Analytics tab)

**Branch:** `feature/live-site-parity` to `main`
**Stories:** DL-01
**Decision:** ADR-031

## Why

Click event names were fixed in code. Authors and analysts need to set the event name and label per component.

## What changed

- New shared dialog tab, `/apps/airline/components/commons/analyticstab`, with "Tracking event name" and "Tracking label". It is added to the Button, List, Teaser and Jump links dialogs.
- New `AnalyticsTracking` Sling Model. It normalises names into `airline:*` (64 characters at most) and labels (100 at most), and has six unit tests.
- Button, List and Teaser HTL wrap Core's script in a `div` with the data attributes. The wrapper is removed when tracking isn't set. Jump links put the attributes on the `nav`.
- `tracking.ts` pushes the authored event with `label`, `linkUrl`, `linkText` and the component ID. `teaser.ts` skips teasers that have their own event.
- Sample content tracks the header Log in button (`airline:header:login`), the footer primary links (`airline:footer:link`) and the hero jump links (`airline:jumplink:click`).

## Verification

- `mvn clean install`: BUILD SUCCESS, including the JaCoCo gate. Deployed to author and publish.
- Playwright: **34 of 34 passed**, including the new Log in and jump-link event tests.
- On author, the merged dialogs show the Analytics tab for all four components.
