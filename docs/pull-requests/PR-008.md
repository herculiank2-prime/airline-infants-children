# PR-008: Jump links component, Core-based header and footer, RTE source edit

**Branch:** `feature/live-site-parity` to `main`
**Stories:** AC-01, SE-01, PF-01, EN-06
**Decision:** ADR-030

## Why

Review feedback on PR-007:
- The header and footer were plain text components.
- Authors couldn't edit link HTML.
- The jump links were locked inside the hero.

## What changed

- New `jumplinks` component, with the `JumpLinks` model and tests. The hero now has a `links` container that only allows jump links (`policy_hero_links`).
- `HeroBanner` loses its jump-link API, so the `models` package moves to 3.0.0.
- New `button` (Core v2) and `list` (Core v4) proxies.
- The header and footer experience fragments are rebuilt from Core Image, Container (navigation role), List, Button and Text. The logos are DAM assets in `/content/dam/airline/brand`.
- RTE source edit is enabled for inline, fullscreen and dialog editing, and in the text policies.
- The link-checker transformer is disabled, because it was stripping the external "Log in" link.
- SCSS for jump links, the header and the footer. UI tests updated.

## Verification

- `mvn clean install` with deploys to author and publish: BUILD SUCCESS, including the JaCoCo gate.
- Playwright against publish: 30 of 30 passed. Two mobile tests timed out once under load, then passed on rerun.
- The "Log in" button renders as an `<a>` again.

Cursor agent: built the components, content, styles and tests, and found the link-checker cause. A human should check source edit and the hero's links container in the author editor.
